# KV Cache:大模型推理加速的第一杠杆

自回归生成时,每生成一个新 token,注意力层都要访问之前所有 token 的 Key 和 Value 向量。如果没有缓存,每步都要对全部历史 token 重算 K/V,计算量随序列长度平方增长。KV Cache 把每层的 K/V 张量缓存在显存里,解码每步只需计算新 token 的 Q/K/V,计算量降为线性。

KV Cache 显存 ≈ 2 × 层数 × 注意力头数 × 头维度 × 序列长度 × 精度字节数 × batch 大小。以 Llama-3-70B 为例(80 层、64 头、128 维、FP16),单条 8K 请求的缓存约 40 GB,超过权重本身。缓存管理因此成为推理系统的核心问题。

分组查询注意力(GQA)让多个 Query 头共享一组 K/V 头,把缓存的头数维度砍到 1/G。MQA 是极端形态。GQA 在质量损失极小的情况下把缓存砍掉 4–8 倍,已成为 Llama 3、Qwen 2.5 等主流模型的默认配置。

把 K/V 存成 FP8 甚至 INT4,显存直接减半再减半。难点在于 K 的异常通道会放大量化误差,需要 per-channel 缩放或专门校准。vLLM 和 TensorRT-LLM 都已支持 FP8 缓存。

借鉴操作系统虚拟内存的思想,把 KV Cache 切成固定大小的 block 按需分配,把显存碎片率从 60–80% 压到 4% 以下,同时让不同请求共享前缀页的物理存储。vLLM 靠这一技术把吞吐提升了 2–4 倍。

缓存越大能容纳的并发请求越少;压缩越狠质量风险越高。实际系统里通常三路并用:GQA 从模型结构上减、量化从精度上减、分页从管理上减。
